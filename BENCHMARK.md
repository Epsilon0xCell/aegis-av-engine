# Benchmark protocol (publishable, and binding on this project)

This protocol exists so that any performance or detection claim
made for Aegis is checkable, and so that no claim drifts past what
was measured. It follows the honest-claim rules from the project's
competitive research.

## What may be claimed

Only axes this harness measures, on a named machine, OS, corpus and
rule-pack version: scan throughput, scan latency, fixture detection
accounting (TP/FP/FN/TN against generated ground truth),
determinism, and (in the multi-OS CI) verdict consistency across
Windows, macOS and Linux for identical corpus files.

## What may never be claimed

General superiority over any commercial product. Vendor lab scores
(AV-TEST, AV-Comparatives, SE Labs) were produced on real-malware
corpora under lab conditions this project does not reproduce, and
quoting them next to Aegis fixture numbers would be a category
error. Comparisons in this repo are against open baselines run
under identical conditions, or against Aegis's own prior versions.

## Corpus

- Clean corpus: generated files of known provenance
  (aegis/corpora.py), listed in benchmarks/corpus/manifest.json.
- Fixture corpus: synthetic, inert malicious-PATTERN fixtures
  generated from marker strings invented for this project, plus the
  EICAR test file as the standard AV smoke test. No real malware
  is used, stored, or distributed, at any stage.
- The manifest hash is embedded in every benchmark report; a report
  without it is not a result.

## Timing

Cold scan (fresh engine, empty verdict cache) and warm scan (cache
populated) are reported separately, as totals and as files/second.
Single-run teaching numbers are labelled as such; release claims
require at least five runs with median and spread, per OS,
reported per OS, never averaged across operating systems.

## Current local result (teaching run, not a release claim)

See benchmarks/results_local.json, generated by
`python -m aegis.cli benchmark` on the maintainer's Linux machine:
35 corpus files, deterministic verdicts, zero false positives on
the 30 clean files, 4 of 5 fixtures flagged. The one missed fixture
is documented, not hidden: a file of pure random bytes matches no
signature and, as an unknown binary type, draws no heuristic score.
That miss is the honest price of a transparent scorecard, and it is
recorded here so the number can only move by improving the engine.

## Release benchmark (v1.0.0, local, Linux)

Protocol applied as written above: 5 runs, median and IQR, cold
and warm separate, corpus identified by manifest hash.

- Corpus manifest SHA-256 (16): `b8698d1fe9d34729`, 36 files
- Cold (fresh engine each run): median 4567.32 files/sec, IQR 13.91
- Warm (verdict cache hot): median 67139.75 files/sec, IQR 105.3
- Deterministic across runs: true
- Machine: the author's Linux development VM; per-OS figures are
  reported separately and never averaged (CI runs the suite on
  Ubuntu, macOS and Windows; a per-OS release benchmark table is
  future work, stated as such rather than filled in).

## Sealed hold-out result (release 1, scored exactly once)

- Commitment: `f1880c8271d7b5003141deb0a8cd6e18c9c321844b0e0c53bbec7036ee6d37c0`
- TP 4, FP 0, FN 1, TN 6 (11 files: mutated fixtures and clean files)
- The one false negative, published verbatim per protocol:
  `holdout_160326_fixture_high_entropy.bin`. Cause: the mutation
  padded the random-bytes fixture with printable text, diluting
  its entropy below the scorecard threshold, and it carries no
  signature. The pure random-bytes fixture was already the
  documented v0.1 miss; this confirms the weakness class rather
  than hiding it. This set is now demoted to the tuning corpus; a
  fresh sealed set will be generated for the next release.
